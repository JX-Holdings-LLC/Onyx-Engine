# Onyx Engine 0.8.0

Onyx's own sampler, chat seam and JSON in place of llama.cpp's `common/` versions, decision images
for clef, lfm2-d1-omni and vllm-d3, and three operator flags.

## Breaking

- **A chat request's `grammar` is applied.** On chat completions the Jinja path used to drop the
  caller's own GBNF without a word, so the output was unconstrained, and a grammar that did not
  parse still streamed a `200`. The grammar now holds the output, and one that does not parse is a
  `400`, streaming or not. Drop `grammar` from chat requests that relied on it being ignored.

## New

- Decision images for `clef`, `lfm2-d1-omni` (images, or one audio clip) and `vllm-d3`, which
  answered `501`; needs `--mmproj`.
- `dimensions` on `/v1/embeddings`: keep the first N values and renormalise (1 to `n_embd`).
- `--api-key-file PATH` and the `ONYX_ENGINE_API_KEY` environment variable, so the key need not
  appear in the process list.
- `--timeout N` (write timeout, default 600 s; the read timeout stays 30 s or less) and
  `--max-request-bytes N` (default 100 MiB, `413` beyond).
- `/props` reports `memory_seq_rm`, what prefix reuse can cut back on this model.

## Changed

- Sampling is Onyx code on `llama.h` (`src/sampler.*`) instead of `common_sampler`. Outputs are
  token-for-token the same as 0.7.0 for the same seed.
- The chat layer sits behind `src/onyx_chat.h`, and Onyx's JSON is `nlohmann::ordered_json` from
  `third_party/nlohmann` instead of `common_json`. Responses are unchanged.
- On recurrent models (Mamba, RWKV) with several slots, the slot whose cache a prompt extends is
  preferred, so more requests reuse their prefix.

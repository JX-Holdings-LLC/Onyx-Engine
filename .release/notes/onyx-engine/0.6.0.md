# Onyx Engine 0.6.0

Onyx Engine becomes a tool anyone can build, run and depend on, with JX Runtime still its
best-supported integration ([plan](https://github.com/JX-Holdings-LLC/Onyx-Engine/blob/main/reports/independent-tool-plan.md), items 1 to 8).

## Breaking

- **A non-loopback `--host` needs `--api-key`.** `--host 0.0.0.0` (or any address other than
  `127.x.x.x`, `localhost` or `::1`) without a key now exits 1 before binding. Pass `--api-key`, or
  `--allow-unauthenticated` if something else guards the port. JX Runtime always binds
  `127.0.0.1` and is not affected.
- **A loopback bind refuses a non-loopback `Host` header** with `403` (DNS-rebinding guard).
  Clients calling `127.0.0.1` or `localhost` are unaffected; a proxy that forwards another `Host`
  to a loopback-bound engine must rewrite it.
- **Readiness moved earlier.** The port opens before the model loads; `/health` and every other
  route answer `503 Loading model` until it is ready. Treat only `200` as ready. JX Runtime
  already does.

## New

- `--port 0` binds a free port, reported on stderr (`listening on http://HOST:PORT (loading)`,
  then `ready on ...`) and as `port` in `/props`.
- `--max-queue N`: beyond `N` waiting requests, `503` with `Retry-After: 1`.
- `--metrics`: Prometheus `/metrics` under llama-server's `llamacpp:*` names.
- `--tick-tokens N`: a per-tick token budget, decode rows first.
- `X-Request-Id` is echoed on every response.
- `encoding_format: "base64"` on `/v1/embeddings`, which the official OpenAI clients send by default.
- Constant-time API-key comparison; an explicit 100 MiB body cap.
- New release archives: `linux-arm64`, `linux-x64-baseline` and `win32-x64-baseline` (no AVX2
  needed), and `linux-x64-vulkan` and `win32-x64-vulkan` (Vulkan GPU). A CPU container image,
  `ghcr.io/jx-holdings-llc/onyx-engine`.

## Building and contributing

- A bare clone builds with CMake, a compiler and Git: the first configure fetches the pinned
  llama.cpp commit. `npm ci && npm run build` still works. `CMakePresets.json` adds release,
  debug, static and GPU presets.
- C++ unit tests under ctest; the smoke suite runs on Windows too; `CONTRIBUTING.md`, a code
  map, and issue and PR templates.

## Documentation

A stability policy, a supervisor guide with Node, Python and shell examples, client and Docker
guides, and a README that leads with what the engine is rather than who spawns it.

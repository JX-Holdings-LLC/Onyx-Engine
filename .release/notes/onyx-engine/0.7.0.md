# Onyx Engine 0.7.0

Memory flags, a queue-wait timeout, HTTP hardening, prefix reuse on sliding-window and recurrent
models, and structured output that fails clearly when it runs out of tokens.

## Breaking

- **Structured output cut by length answers `400`.** Under `json_schema` or `response_format`, a
  response that reaches `max_tokens` or the context limit used to be a `200` with half an object.
  It is now a `400` (`invalid_request_error`) naming the limit; a stream ends on that error frame
  without `[DONE]`. Raise `max_tokens` if you see it.
- **`{"type":"json_object"}` without a schema is now held to a JSON object;** it was unconstrained.
- **cpp-httplib v0.62.0 parses strictly:** an HTTP/1.1 request without `Host` gets `400`.
- **Request bodies nested deeper than 64 levels get `400`.**

## New

- `-ctk`/`--cache-type-k`, `-ctv`/`--cache-type-v`: KV cache types (`q8_0` roughly halves KV memory).
- `--cpu-moe`, `--n-cpu-moe N`, `-ot`/`--override-tensor PATTERN=BUFFER_TYPE`: keep MoE experts in
  RAM and place tensors by name.
- `--queue-timeout N`: `503` with `Retry-After: 1` for a request that waits `N` seconds for a slot;
  `onyx:requests_timed_out_total` in `/metrics`.

## Changed

- Prefix reuse now works on sliding-window models (Gemma, gpt-oss), and on recurrent and hybrid
  models for an exact continuation, instead of being switched off for them at load.
- The read timeout is 30 seconds (was 600); the write timeout is unchanged.
- cpp-httplib v0.54.1 → v0.62.0.
- Tokenization and batch helpers are Onyx code on `llama.h` (`src/llama_util.*`), the first part
  of the plan to stop linking llama.cpp's `common/`.
